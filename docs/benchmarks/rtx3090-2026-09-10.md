# RTX 3090 × 2 ベンチマーク（2026-09-10）

単一 GPU と 2 GPU の同一入力を比較した。5.12 億 bit の乗算は 176.008 ms → 146.554 ms（1.20 倍）、1 億 bit の 3 乗は 104.793 ms → 91.167 ms（1.15 倍）だった。二乗の改善は小さく、入力サイズによっては 2 GPU の方が遅い。

## 測定条件

- GPU：NVIDIA GeForce RTX 3090 24 GiB × 2。単一は GPU 0、複数は GPU 0 と 1。
- GPU 間接続：PHB。P2P は両方向とも利用不可で、分散時の転送はページ固定 CPU メモリ経由。
- VM：28 vCPU（QEMU Virtual CPU version 2.5+）、メモリ約 3.82 GiB。
- Python 3.12.3 / CuPy 14.0.1 / CUDA 13.0 / NVIDIA driver 580.173.02 / gmpy2 2.3.1 / GMP 6.3.0。
- 各ケース：ウォームアップ 2 回、本計測 7 回の中央値。seed=42、分散開始 64,000,000 bit、transfer=auto、各段階のタイムアウト 30 秒。
- GPU の完了同期と分散転送は計測に含む。入力生成・GPU 入力変換・CPU 参照計算・CPU への結果回収と照合は計測から除く。
- バックエンドは別プロセスで順番に測定。同じバックエンド内ではキャッシュを再利用。
- 全 79 ケース成功。本計測 553 回とウォームアップ 158 回の全結果を GMP と照合し、バックエンド間・重複測定間の入力ハッシュ一致を確認。不一致・タイムアウト・OOM なし。

## 全演算の比較

時間の単位は ms。倍率は「単一 GPU ÷ 2 GPU」で、1 より大きいほど 2 GPU が速い。NTT はウォームアップ込みの分散乗算回数。NTT=0 の行は GPU 0 だけで処理されており、時間差を分散による高速化とは解釈できない。

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 加算 | 1,000,000 | 0.059 | 0.158 | 0.010 | 0.37× | 0 |
| 加算 | 10,000,000 | 0.217 | 0.336 | 0.505 | 0.65× | 0 |
| 加算 | 100,000,000 | 0.381 | 0.379 | 2.143 | 1.01× | 0 |
| 減算 | 1,000,000 | 0.085 | 0.076 | 0.010 | 1.13× | 0 |
| 減算 | 10,000,000 | 0.229 | 0.220 | 0.163 | 1.04× | 0 |
| 減算 | 100,000,000 | 0.479 | 0.450 | 2.114 | 1.07× | 0 |
| 乗算 | 1,000,000 | 0.337 | 0.322 | 1.900 | 1.05× | 0 |
| 乗算 | 10,000,000 | 3.837 | 3.792 | 59.508 | 1.01× | 0 |
| 乗算 | 100,000,000 | 36.295 | 31.989 | 873.292 | 1.13× | 9 |
| 二乗 | 1,000,000 | 0.622 | 0.257 | 2.343 | 2.42× | 0 |
| 二乗 | 10,000,000 | 2.797 | 2.760 | 42.390 | 1.01× | 0 |
| 二乗 | 100,000,000 | 25.189 | 25.687 | 589.320 | 0.98× | 9 |
| 除算 | 1,000,000 | 4.118 | 11.285 | 4.377 | 0.36× | 0 |
| 除算 | 10,000,000 | 20.993 | 27.786 | 61.146 | 0.76× | 0 |
| 除算 | 100,000,000 | 245.987 | 240.977 | 953.758 | 1.02× | 36 |
| 剰余 | 1,000,000 | 4.162 | 11.148 | 4.179 | 0.37× | 0 |
| 剰余 | 10,000,000 | 21.228 | 27.912 | 61.649 | 0.76× | 0 |
| 剰余 | 100,000,000 | 239.424 | 240.756 | 946.074 | 0.99× | 36 |
| 3 乗 | 1,000,000 | 0.523 | 1.324 | 7.206 | 0.40× | 0 |

除算・剰余の除数は入力 bit 数の半分。乗算は同じ bit 数の 2 整数、二乗は同じオブジェクト、3 乗は指定 bit 数を底にした累乗。

## 大きな乗算・二乗の追加測定

全演算の比較を終えてから別プロセスで再測定した。全行で分散 NTT が 9 回実行され、転送は CPU メモリ経由だった。

| 演算 | 入力 bit | 単一 GPU（ms） | 2 GPU（ms） | 倍率 |
| --- | ---: | ---: | ---: | ---: |
| 乗算 | 64,000,000 | 16.627 | 17.012 | 0.98× |
| 乗算 | 100,000,000 | 36.308 | 32.578 | 1.11× |
| 乗算 | 256,000,000 | 80.145 | 70.328 | 1.14× |
| 乗算 | 512,000,000 | 176.008 | 146.554 | 1.20× |
| 二乗 | 64,000,000 | 11.523 | 13.841 | 0.83× |
| 二乗 | 100,000,000 | 25.188 | 26.200 | 0.96× |
| 二乗 | 256,000,000 | 55.346 | 55.865 | 0.99× |
| 二乗 | 512,000,000 | 121.230 | 115.306 | 1.05× |

この構成では 6,400 万 bit の乗算が 0.98 倍、二乗が 0.83 倍で、既定の分散開始サイズが常に速度改善を保証するわけではない。1 億 bit の乗算は独立した 2 回の測定で 1.11〜1.13 倍だった。

時間には VM のスケジューリングや GPU クロックの変動も含まれる。小さい入力の結果にはばらつきがあり、微小な差から一般的な性能差は断定できない。P2P 接続や 4 GPU での性能は今回の測定対象外。

## 再実行

リポジトリルートで実行する。この VM ではホスト側 CUDA ドライバを使用するため LD_LIBRARY_PATH を指定した。

```bash
docker compose exec -T -e LD_LIBRARY_PATH=/usr/lib/x86_64-linux-gnu:/usr/local/cuda/lib64 tabai python benchmarks/benchmark.py --gpu-mode both --devices 0 1 --backends tabai gmpy2 --bits 1000000 10000000 100000000 --pow-exponents 3 --warmup 2 --repeat 7 --timeout 30 --output /mnt/benchmark-overview.json

docker compose exec -T -e LD_LIBRARY_PATH=/usr/lib/x86_64-linux-gnu:/usr/local/cuda/lib64 tabai python benchmarks/bench_mul.py --gpu-mode both --devices 0 1 --backends tabai --bits 64000000 100000000 256000000 512000000 --warmup 2 --repeat 7 --timeout 30 --output /mnt/benchmark-scaling.json
```
